# FO48U Firmware Analysis — Working Notes

Status: **in progress**. Goal: reverse-engineer the Gigabyte AORUS FO48U firmware
(Realtek RTD2718, banked 8051) to fix bugs and unlock features (APCS flag bug,
ADCS in OSD, AOCS reliability, ASBL tuning, FreeSync/HDR fixes).

## Target

- File: `firmware/F08-20221115/FO48U_MP_F08_20221115_r9120_SIDEKICK_USE.bin`
- Size: 2,031,616 bytes (0x1F0000)
- MD5: `d4324c6c88abea48b1ee896f7e14ee9f`
- Identified as: `FW: F08  20221115`, panel `LG LE48AOD EPA4`, scaler `RTD2718`.

## Flash layout (observed)

| Region | Range | Notes |
|---|---|---|
| Code (banked) | 0x000000 – 0x13FFFF | 8051 code, ~1.25 MB |
| Erased (0xFF) | 0x140000 – 0x1AFFFF | 384 KB unused flash |
| Gamma/LUT table | 0x1B0000 – 0x1CFFFF | 16-bit gamma curve + brightness table |
| OSD font / LUT | 0x1D0000 – 0x1EFFFF | duplicated 64 KB block (backup) |
| (end) | 0x1F0000 | |

Bank switching on Realtek RTD27xx uses SFRs (typically 0x60/0x61 bank select),
with a common bank (0x0000–0x7FFF) and switchable banks (0x8000–0xFFFF).
The 8051 address space is 64 KB, so the 2 MB image is banked.

## Confirmed findings

- Scaler string: `RTD2718` (at 0xb9b0a and 0xc5378).
- Panel string: `LG LE48AOD EPA4` (0xb9af2).
- Firmware ID: `FW : F08  20221115` (0xb9ada).
- VCP/MCCS descriptor at 0xab381 (monitor responds to DDC/CI VCP codes).
- BootCode / UserCode / UserBoot segment labels at 0xb9ab8.
- Reset vector at 0x0000 → `ljmp 0x4e0c`; interrupt vectors at 0x0003, 0x000b, etc.
- USB control endpoint (from community): Realtek vendor HID `0BDA:1100`.

## New findings (deep dive)

- Reset vector 0x0000 → `ljmp 0x4e0c` (boot/init). Interrupt vectors at 0x0003, 0x000b, …
- Boot code at 0x4e0c clears IRAM 0x00–0xff (except 0x30), checks XDATA 0xffff, copies
  parameter block 0xc500 → 0x... (54 bytes), sets SP=0x59, then `ljmp 0x4e72` / 0x3526.
- `mov 0x7a, #2` "bank switch" hits were a false positive: 0x75 bytes inside `mov dptr,#imm16`
  (0x90 0x75 0x7a) instructions in a repeated jump table. Real bank-switch mechanism TBD.
- Ghidra 8051 auto-analysis found 0 functions (no auto-discovery). Need manual function
  creation at call targets or use radare2 `af`/`aac`. Banked code means per-bank loading.
- Service menu entry (hold UP on joystick during power-on) is handled in boot code around
  the joystick/GPIO check before the main loop; exact address TBD (search for GPIO reads
  in bank0 init).
- OSD/menu text is not stored as ASCII in bank0; likely compressed or in a separate
  resource region (0x1d0000 OSD block) or generated by scaler OSD engine.

## Next concrete steps

1. Use radare2 to mark functions at all `lcall` targets (high-frequency ones first) and
   run `af` + `pdf` to get disassembly per function.
2. Search boot code for GPIO/joystick reads to find service-mode flag set.
3. Identify the APCS timer: search for constant 0x0E10 (4h in minutes? 240? 14400s) or
   modulo operations in common code.
4. Determine bank-switch SFR by examining RTD2718 datasheet / comparing with RTD2660 spec
   (page 355 "Bank Switch"): likely an SFR in 0x60-0x7f range written before `ljmp`
   into 0x8000-0xffff. Search for `mov direct, #imm` immediately followed by `ljmp 0x8xxx`.
5. Once bank mechanism known, split image and decompile each bank in Ghidra.

## Safety

- Always keep the original `FO48U_MP_F08_20221115_r9120_SIDEKICK_USE.bin` for recovery.
- Flashing modified firmware may brick the monitor. Test on a sacrificial unit.
- Do not distribute modified firmware without clear "unofficial / at your own risk" labeling.
